# OData Service Specification: `ZGCP_TRANSLATION_SRV`

## 1. Task

Consume the OData V2 service `ZGCP_TRANSLATION_SRV` in the SAPUI5 / Fiori application and implement the following functions:

1. Display the list of translated texts, with filtering and paging.
2. Display a single translated text.
3. Create a translated text.
4. Change a translated text.
5. Delete a translated text.

This document describes only the OData service (the contract). The design and implementation in the app is up to the UI5 team. The service is deployed in DEV.

---

## 3. Entity: `TranlsatedTexts`

| Property | OData type | Create | Update | Filter | Description | Example |
|---|---|---|---|---|---|---|
| `GuiNo` | `Edm.Guid` (key) | No | No | Yes | Unique ID, generated by the server | `005056a9-001b-1fd1-b09c-a3ad91ab3caf` |
| `SrcLang` | `Edm.String` | Yes | Yes | Yes | Source language code | `EN` |
| `TarLang` | `Edm.String` | Yes | Yes | Yes | Target language code | `DE` |
| `SrcText` | `Edm.String` | Yes | Yes | No | Source text | `Hello` |
| `TarText` | `Edm.String` | Yes | Yes | No | Target text | `Hallo` |
| `TransBy` | `Edm.String` | No | No | Yes | User who created the entry (set by server) | `D10045` |
| `TransOn` | `Edm.DateTime` | No | No | Yes | Creation date (set by server) | `/Date(1791158400000)/` |
| `TransAt` | `Edm.Time` | No | No | Yes | Creation time (set by server) | `PT23H19M39S` |

Rules:

- `GuiNo`, `TransBy`, `TransOn`, `TransAt` are set by the server. Do not send them. Any value sent is ignored.
- `SrcLang`, `TarLang`, `SrcText` and `TarText` are **mandatory** on create and update. If one is empty the service returns HTTP 400.
- Send language codes in upper case, for example `EN`, `DE`.
- `TransOn` is a date only (midnight). `TransAt` is a time of day in ISO 8601 duration format.

## 4. Operations

| Operation | HTTP method | URL (after the service root) | Success status |
|---|---|---|---|
| Read list | GET | `TranlsatedTextsSet` | 200 |
| Read single | GET | `TranlsatedTextsSet(guid'<GuiNo>')` | 200 |
| Create | POST | `TranlsatedTextsSet` | 201 |
| Update | PUT | `TranlsatedTextsSet(guid'<GuiNo>')` | 204 |
| Delete | DELETE | `TranlsatedTextsSet(guid'<GuiNo>')` | 204 |

**Key format:** `guid'<value>'` with **no space** between `guid` and the opening quote.

```
TranlsatedTextsSet(guid'005056a9-001b-1fd1-b09c-a3ad91ab3caf')
```

### 4.1 Read list

```
GET /sap/opu/odata/sap/ZGCP_TRANSLATION_SRV/TranlsatedTextsSet?$format=json
```

Response (one entry shown):

```json
{
  "d": {
    "results": [
      {
        "__metadata": {
          "uri": ".../TranlsatedTextsSet(guid'005056a9-001b-1fd1-b09c-83d02bce1caf')",
          "type": "ZGCP_TRANSLATION_SRV.TranlsatedTexts"
        },
        "GuiNo": "005056a9-001b-1fd1-b09c-83d02bce1caf",
        "SrcLang": "EN",
        "SrcText": "Hello",
        "TarLang": "DE",
        "TarText": "Hallo",
        "TransBy": "D10045",
        "TransOn": "/Date(1791158400000)/",
        "TransAt": "PT23H12M37S"
      }
    ]
  }
}
```

**Filtering** (`$filter`) is supported on `GuiNo`, `SrcLang`, `TarLang`, `TransBy`, `TransOn`. It is applied in the database.

```
?$filter=SrcLang eq 'EN' and TarLang eq 'DE'
?$filter=TransBy eq 'D10045'
```

`SrcText` and `TarText` cannot be used in `$filter` or `$orderby`.

**Paging** with `$top` and `$skip` is supported and applied in the database.

```
?$top=20&$skip=40
```

- If `$top` is not sent, the service returns at most **100** entries.
- Results are sorted by `GuiNo`. `$orderby` is not applied by the backend.
- `$count` and `$inlinecount` are **not implemented**. The total number of records is not available from the service.

### 4.2 Read single

```
GET /sap/opu/odata/sap/ZGCP_TRANSLATION_SRV/TranlsatedTextsSet(guid'005056a9-001b-1fd1-b09c-a3ad91ab3caf')
```

Returns the entry in the same structure as one list item. Returns 404 if it does not exist.

### 4.3 Create

```
POST /sap/opu/odata/sap/ZGCP_TRANSLATION_SRV/TranlsatedTextsSet
Content-Type: application/json
Accept: application/json
X-CSRF-Token: <token>

{
  "SrcLang": "EN",
  "TarLang": "DE",
  "SrcText": "Hello1",
  "TarText": "Hallo1"
}
```

Response **201 Created**. The body contains the created entry, including the generated `GuiNo`, `TransBy`, `TransOn` and `TransAt`.

### 4.4 Update

```
PUT /sap/opu/odata/sap/ZGCP_TRANSLATION_SRV/TranlsatedTextsSet(guid'005056a9-001b-1fd1-b09c-a3ad91ab3caf')
Content-Type: application/json
X-CSRF-Token: <token>

{
  "SrcLang": "EN",
  "TarLang": "DE",
  "SrcText": "Hello updated",
  "TarText": "Hallo aktualisiert"
}
```

Response **204 No Content** (no body). Send all four editable fields. Only these four are changed. `TransBy`, `TransOn` and `TransAt` keep their original values. Read the entry again to get the saved values.

### 4.5 Delete

```
DELETE /sap/opu/odata/sap/ZGCP_TRANSLATION_SRV/TranlsatedTextsSet(guid'005056a9-001b-1fd1-b09c-a3ad91ab3caf')
X-CSRF-Token: <token>
```

Response **204 No Content**. Deletion is permanent.

### 4.6 CSRF token

POST, PUT and DELETE need a valid CSRF token.

1. Send `GET <service root>` with the header `X-CSRF-Token: fetch`.
2. Read the token from the `X-CSRF-Token` header of the response.
3. Send it in the `X-CSRF-Token` header of every change request.

If the token is missing or expired the service returns **403**.

## 5. Error behavior

Error responses use the standard OData V2 error structure. The text to show the user is in `error.message.value`.

```json
{
  "error": {
    "code": "...",
    "message": { "lang": "en", "value": "Translated text not found" }
  }
}
```

| Situation | HTTP status | Message (example) |
|---|---|---|
| Mandatory field empty (create or update) | 400 | Source/target language and text are mandatory |
| Key is not a valid GUID (for example a non-hex character or wrong length) | 400 | Malformed URI literal syntax |
| Key syntax wrong (for example a space after `guid`) | 400/404 | The request URI contains an invalid key predicate |
| Entry with this key does not exist (read single, update, delete) | 404 | Translated text not found |
| Wrong entity set name | 404 | Resource not found for the segment ... |
| CSRF token missing or expired | 403 | CSRF token validation failed |
| User not authorized for the service | 403 | (authorization error) |
| Unexpected backend error | 500 | (internal error) |

The first two error messages for malformed keys come from the Gateway framework, not from the service logic.

## 6. Known limitations

1. No `$orderby` and no `$count` / `$inlinecount` (see 4.1).
2. If `$top` is not sent, a maximum of 100 entries is returned.
3. `SrcText` and `TarText` are long text fields: no filtering or sorting on them.
4. No duplicate check: posting the same text twice creates two entries.
5. No change tracking: only the creator and creation time are stored. Updates are not logged.
6. The `uri` and `id` values in `__metadata` may contain `http://...:8000`. Ignore the host part and call the service through the configured HTTPS path or destination.
7. `SrcLang` and `TarLang` currently allow up to 40 characters in the metadata. The backend may later restrict them to 2 characters. Always send ISO-style codes such as `EN`, `DE`.

## 7. How to test the service (before building the app)

Use Postman, the browser, or the SAP Gateway Client (`/IWFND/GW_CLIENT`).

1. `GET .../$metadata` – confirms the service is available and shows the exact names.
2. `GET .../TranlsatedTextsSet?$format=json` – lists the entries. Copy one `GuiNo`.
3. `GET .../TranlsatedTextsSet(guid'<GuiNo>')` – returns one entry (200).
4. `PUT` the same URL with the body from 4.4 – returns 204.
5. `GET` the same URL again – shows the new text.
6. `DELETE` the same URL – returns 204. A new `GET` returns 404.
7. `POST .../TranlsatedTextsSet` with the body from 4.3 – returns 201.

For backend errors, contact the backend developer with the timestamp or transaction ID from the error response, so the entry in `/IWFND/ERROR_LOG` can be found.
